# Database layout

## What is authoritative

`schema_baseline.sql` is the source of truth. It was generated by querying
`pg_catalog` on the live project, not by concatenating the files in `archive/`.

Everything in `archive/` is kept for history only. Do not run those files. They
contradicted each other and, more importantly, contradicted the database:

- The same policy names were created in three different files, some with a
  preceding `DROP POLICY IF EXISTS` and some without, so the result depended
  entirely on what order someone happened to run them in.
- Two migrations both claimed the number `003`.
- `security_addendum.sql` was listed as applied in `docs/SECURITY.md` for weeks
  and had never actually been run. The artworks bucket had no size limit and no
  MIME allow-list, uploads were not confined to a family's folder, and deletes
  were still scoped to whoever uploaded the file. Migration `009` applied it for
  real, and the result was verified by query.

That last one is the reason this README exists. A policy written in this repo is
not a policy that is live.

## Making a change

Add a new file to `migrations/`. Never edit `schema_baseline.sql` to introduce a
change, and never add another loose top-level `*.sql` script.

Note that `migrations/002`-`009` predate the baseline and are already encoded in
it, so they do not need re-running. They also use a plain `NNN_` prefix rather
than the timestamp format the Supabase CLI expects, which is why
`supabase db push` is not the tool for this directory today.

## Verifying against production

Never trust this directory to tell you what is live. Ask the database:

```bash
supabase db query --linked "
  select schemaname, tablename, policyname, cmd, roles::text
  from pg_policies where schemaname in ('public','storage')
  order by 1,2,4,3;"

supabase db query --linked \
  "select id, public, file_size_limit, allowed_mime_types::text from storage.buckets;"
```

`supabase db query --linked` runs through the Management API, so it needs
`supabase login` but not Docker. `supabase db dump` does need Docker.
